# 2026-11-26 20:37 — the fix landed, in shape A

**What was done.** The three UI path builders now ask the service where the
Vault's files are served from instead of assuming the repository:

| Piece | Change |
| --- | --- |
| `desktop/service/files.mjs` | `boardBase()` returns `files.url(vault.root)` |
| `desktop/service/server.mjs` | `/api/bootstrap` carries `vaultRoot` and `boardBase` |
| `src/desktop/client.ts` | `contentUrl()` becomes `boardUrl(folder, file)` |
| `src/App.tsx` | the report URL and the Markdown path build on the Vault |
| `src/components/ReportViewer.tsx` | the Markdown preview resolves against `vaultRoot` |
| `src/components/Sidebar.tsx` | the board icon builds on `boardUrl` |

**Which shape, and why.** Shape A from `open-questions.md` Q1 — a Vault-rooted
`boardBase` plus `vaultRoot`, with the UI still building the path. It is the
smallest of the three, it keeps the default Vault **byte-identical** (Q2), and
it needed no new route and no asynchronous report URL.

**The scope the UI now holds.** The grant behind `boardBase` covers the whole
Vault, not one board (Q3). That is the same scope the repository grant already
had, so it is not a new kind of exposure, but it is a new scope. A per-board
scoped grant is still available if it ever needs narrowing.

**Evidence.** `npm test` on 2026-11-26 20:37: 330 tests, 323 pass, 0 fail,
7 skipped. The Vault test passes by name: *"a Vault outside the repository holds
the boards and serves its reports"*.

**Still open, and not part of this fix.** The stale copies of three boards under
`<repo>/workspace/` (Q6) are untouched — the ticket's rule was not to move boards
back there, and deleting them afterwards is the owner's call.
